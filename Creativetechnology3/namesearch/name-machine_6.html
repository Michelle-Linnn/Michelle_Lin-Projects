About

A Rube Goldberg machine that reads museum collections

You type one first name. The machine looks for an artist with that name in museum databases, takes one of their works, reads its colour, and uses that colour to pull prints, posters, textiles and illustration out of other collections. Each image then decides where the machine goes next. At the end the same material is recomposed as a moodboard.

Controls

Tune → Colour sets how saturated the machine wants things. At the vivid end it only asks the Art Institute for works whose catalogued colour saturation is high, ranks greyish images lower, pushes the moodboard palette toward pure hues, and boosts image saturation on screen. Look for chooses which kinds of works each colour searches: illustration (prints, drawings, illustrated books), posters and graphic design, texture and pattern (textiles and close-up surfaces), and art photography.

Branch / Ring changes how the rope web spreads: Branch lets it grow outward freely; Ring pulls every card onto a circle by how many steps it is from the name, so the whole run reads as rings around the trigger. Moodboard has four layouts (Editorial, Gallery, Scrapbook, Poster); Recompose reshuffles the palette and image choice within the current layout.

Responses to the brief

How can we build Rube Goldberg systems in the digital realm?

By treating the answer from one database as the question for the next, without asking whether that makes sense. A name becomes an artist, an artist becomes a painting, a painting becomes a hue in degrees, a hue becomes a query for posters and textiles nobody connected to that painter. The hand-off rules are the mechanism, and each one is written on the rope.

What kind of data could be passed around?

Names, museum agent IDs, object IDs, HSL colour values, hex codes, colour names, places of origin, maker IDs, subject tags, image URLs. Some of it is metadata catalogued by curators; some is read from pixels in your browser. When neither exists, the machine takes another route.

What services could be chained together to produce unexpected outcomes?

Museum open-access APIs are deep, free and richly described: the Art Institute of Chicago stores the dominant colour of each artwork, so a painting can search for textiles by hue. The Met's Drawings and Prints department and Cleveland's open access add catalogued subjects and posters; Openverse adds Creative Commons illustration, pattern and texture. None of these services know about each other.

What would the triggers look like, and the end results?

The trigger is the smallest gesture, one word. The end result is two things: a web of images strung on rope, each tied to the value that summoned it, and a moodboard composed from it. Type the same name twice and you get a different web, because every image rolls a die.
